# JavaScript Runtime and Async

Небольшой проект на чистых HTML, CSS и JavaScript для практики: замыкания, Call Stack, Promise, async/await, Event Loop, задачи и микрозадачи.

**Запуск:** открыть `index.html` в браузере.

**Что есть в приложении:**
- три задачи (Load Users, Load Posts, Load Comments) со статусом, счётчиком запусков и временем загрузки;
- кнопка **Run All Tasks**;
- кнопка **Compare** (sequential vs concurrent);
- кнопка **Run Event Loop Demo**.

## 1. Как замыкание делает счётчик приватным

```js
function createTask(name) {
  let count = 0;
  return {
    run() { count++; /* ... */ },
    getCount() { return count; },
    reset() { count = 0; },
  };
}
```

`count` объявлена внутри `createTask`, поэтому снаружи к ней нет доступа: `task.count` вернёт `undefined`. Читать и менять её можно только через методы, которые «помнят» эту переменную (замыкание). Каждый вызов `createTask` создаёт свою копию `count`, поэтому у разных задач счётчики независимы.

## 2. Как работает Call Stack (пример из приложения)

Пользователь нажимает Run на карточке:

```
click handler → runOne(task) → task.run() → new Promise(executor) → setTimeout(...)
```

Каждый вызов кладётся на стек. `setTimeout` только регистрирует таймер и сразу завершается, потом по очереди завершаются executor, `run()` (он вернул pending Promise) и обработчик. Стек становится пустым. Сам колбэк таймера выполнится позже, уже на новом пустом стеке.

## 3. Как JavaScript продолжает работать, пока ждёт `setTimeout`

Таймер считает не JavaScript, а браузер (Web API). JS только говорит: «через N мс положи этот колбэк в очередь». Пока браузер ждёт, стек свободен: страница реагирует на клики, запускаются другие задачи. Когда время вышло, колбэк попадает в Task Queue, а Event Loop переносит его в стек, как только тот освободится.

## 4. Event Loop: прогноз и реальный результат

Код демо:

```js
async function asyncFn() {
  log("G: async start");
  await Promise.resolve();
  log("H: async after await");
}

log("A: script start");
setTimeout(() => log("B: timeout 1"), 0);
Promise.resolve().then(() => log("C: promise 1"));
setTimeout(() => log("D: timeout 2"), 0);
Promise.resolve().then(() => log("E: promise 2"));
asyncFn();
log("F: script end");
```

**Мой прогноз (написан до запуска):**

```
<ВПИШИ СВОЙ ПРОГНОЗ СЮДА>
```

**Реальный вывод:**

```
A, G, F, C, E, H, B, D
```

**Почему так:**

1. **Call Stack.** Синхронный код выполняется целиком: `A`, затем `G` (часть `asyncFn` до `await` тоже синхронная), затем `F`. Попутно таймеры уходят в браузер, а `.then` и продолжение после `await` встают в Microtask Queue.
2. **Microtask Queue.** Когда стек пуст, Event Loop выполняет **все** микрозадачи в порядке постановки: `C`, `E`, `H`. Продолжение `asyncFn` встало в очередь после двух `.then`, поэтому `H` идёт после `E`.
3. **Task Queue.** Только теперь Event Loop берёт по одной задаче из очереди таймеров: `B`, затем `D`. Между ними он снова проверяет микрозадачи (здесь их уже нет).

Даже `setTimeout(..., 0)` выполняется после всех Promise-колбэков.

## 5. Разница между tasks и microtasks

| | Task (макрозадача) | Microtask |
|---|---|---|
| Примеры | `setTimeout`, события кликов | `.then/.catch`, код после `await` |
| Очередь | Task Queue | Microtask Queue |
| Когда выполняется | по **одной** за цикл Event Loop | **все сразу**, после каждой задачи и до следующей |

Микрозадачи всегда имеют приоритет: пока очередь микрозадач не пуста, следующая задача не начнётся.

## 6. Как обрабатываются несколько Promise и ошибки

- Загрузка падает через `reject` (в async-варианте через `throw`), когда `Math.random()` меньше шанса ошибки.
- Для одной задачи используется `try/catch` вокруг `await`, поэтому ошибка не превращается в unhandled rejection и не ломает остальной код. Она отражается в статусе `failed`.
- Для нескольких задач используется **`Promise.allSettled`**. Он ждёт, пока завершатся **все** Promise (и успешные, и упавшие), и возвращает массив `{ status, value | reason }`. Поэтому «All tasks finished» показывается только после самой медленной задачи.
- `Promise.all` не подходит: он отклоняется при первой ошибке, не дожидаясь остальных.

## 7. Sequential и Concurrent

```js
// Sequential: каждая задача ждёт предыдущую
for (const t of tasks) await runOne(t);

// Concurrent: запускаем все сразу и ждём всех
await Promise.allSettled(tasks.map(runOne));
```

- **Sequential:** время задач **складывается**. Например, 1200 + 800 + 1500 = 3500 мс.
- **Concurrent:** все таймеры тикают одновременно, общее время равно **самой долгой** задаче, то есть max(1200, 800, 1500) = 1500 мс.

Разница в том, что ожидание таймеров идёт в браузере, а не в нашем коде. JavaScript остаётся однопоточным, но пока задачи ждут, он успевает запустить остальные. Время задач случайное, поэтому цифры меняются, а закономерность остаётся: sequential ≈ сумма, concurrent ≈ максимум.
